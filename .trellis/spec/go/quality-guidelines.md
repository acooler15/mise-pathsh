# 质量要求

> 提交 / 检查前以下命令全部通过。**PATH 中有 `go` 就直接执行**
> （mise 激活后其 shims 已在 PATH 里）；PATH 中没有时先 `mise install`
> 再加 `mise exec --` 前缀回退执行：

```bash
gofmt -l .      # 输出必须为空
go vet ./...
go test ./...
go build ./...
```

---

## 测试要求

- 路径转换逻辑必须有**表驱动测试**（Go 惯例）。
- 端到端测试以 `sample-activate.sh`（或其子集）为 fixture，至少断言：
  1. **结构无损**：注释、引号风格、变量展开、语句顺序全部保留；
  2. **转换正确**：PATH 值为 POSIX 形态（`/c/...`，冒号分隔）；
  3. **幂等**：对已转换的输出再做一次转换，结果不变。
- fixture 放 `testdata/`；`sample-activate.sh` 本身只读，测试用它的副本。

## 禁止事项

- 忽略 error（`_ =`）、吞掉解析库返回的位置信息。
- 在 `internal/` 库代码里直接打印。
- 手写解析逻辑替代开源解析库。
- 修改 `sample-activate.sh`（它是原始样本）。

## 评审重点

- 转换规则的**保守性**：宁可漏转，不可错转——错转一个路径会让
  用户的 shell 直接坏掉，漏转只是少优化一处。
- 结构保真：任何 diff 都应能解释为"字符串字面量内部的变化"。
